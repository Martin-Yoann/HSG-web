# Loading optimization — 2026-11-02

## Implemented

- Retain responsive WebP delivery and high-priority hero preload. Hero variants use quality 65, photo-strip variants use quality 60, and other photos retain quality 75. Allow exactly these three quality settings in Next image configuration. Original image/video files are unchanged.
- Match the photo strip's `sizes` breakpoint to its actual 900px CSS breakpoint. Add a 520px image candidate for 260px cards on DPR 2 screens; these previously selected 640px images on phones and could select 828px images on tablets.
- Select deferred native video posters using the displayed video width and screen pixel density. The browser chooses from the responsive image candidates before the URL is assigned to `video.poster`. Loaded posters adapt to resized layouts. The video itself remains `preload="none"`; poster loading does not call video playback or load.
- Keep reduced-motion, weak-network behavior, pause controls, existing content and all navigation interactions.

## Reproducible measurement

After `npm run build` and starting the production server on port 3100:

```sh
node scripts/measure-loading.mjs test-results/loading-measurement.json
```

Set `PERF_BASE_URL` to measure another deployment. The script uses a fresh browser context, disables browser cache, applies 120ms latency, 1.6Mbps download and 4x CPU slowdown, then observes until three seconds after load. Image optimizer cache on the server can be warm. Byte totals cover completed responses; unfinished background-video transfers are excluded. These are local laboratory snapshots, not Lighthouse scores, real-user percentiles or INP measurements.

| Page / viewport | Completed bytes before | Completed bytes after | Reduction | Image bytes before → after | LCP before → after |
| --- | ---: | ---: | ---: | ---: | ---: |
| Chinese home / 390px DPR 2 | 513,110 | 419,612 | 18.2% | 301,116 → 204,966 | 1,616 → 1,756ms |
| English about / 390px DPR 2 | 338,197 | 329,172 | 2.7% | 143,431 → 133,364 | 1,756 → 1,668ms |
| Chinese home / 1440px DPR 1 | 593,394 | 548,353 | 7.6% | 381,400 → 333,707 | 3,152 → 2,892ms |

The mobile home image payload decreased by 31.9%. CLS was zero in these measurement windows. LCP moved in both directions, so this pass establishes smaller transfers, not a statistically demonstrated load-time improvement. No claim is made about unobserved scrolling, whole-session bandwidth or field performance. The final resize-observer addition does not affect initial poster downloads because unvisited videos remain uninitialized.

An additional mobile OPC poster sample selected 750px at quality 65 (12,268 WebP body bytes), compared with the former 1920px quality-75 variant (22,340 bytes): 45.1% smaller when that poster is reached by scrolling. This is separate from the initial-page totals above.

## Verification and limits

- Build and route/asset checks; loading, pause/captions, keyboard navigation, mobile home and all 28 source-content counterparts checked in browser regression tests.
- Tests explicitly verify phone/tablet strip candidate selection, correct density for phone and full-width desktop video posters, poster updates after resizing, and no automatic movie request while loading a poster.
- Compression was reviewed in browser previews; this is not a pixel-equivalence claim. Original assets remain available, and individual images can override quality if necessary.
- Next priorities: repeat measurements under representative production/cache conditions and on physical phones, then consider further image sizing or video encoding based on evidence. No analytics scripts or cookies were added.
